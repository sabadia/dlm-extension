# E0.6: the daemon's origin checks with real extension requests

**Question.** The plan assumed Firefox's `moz-extension://<uuid>` origin could not be allow-listed and that REST calls
from an extension would be refused by the daemon's CORS and cross-origin protection.

**Result.** That assumption was wrong. The daemon (v0.5.0), started with **no** `allowed_origins`, accepted every
request from both extensions:

| What the daemon's side saw      | Chrome 156                | Firefox 159              |
| ------------------------------- | ------------------------- | ------------------------ |
| `Origin` on GET                 | absent                    | absent                   |
| `Origin` on POST                | `chrome-extension://<id>` | `moz-extension://<uuid>` |
| `Sec-Fetch-Site`                | `none`                    | `same-origin`            |
| `OPTIONS` preflight             | never sent                | never sent               |
| `POST /v1/capture` with token   | 201                       | 201                      |
| `GET /v1/tasks` with `If-Match` | 200                       | 200                      |
| SSE `GET /v1/events`            | `text/event-stream`       | `text/event-stream`      |

`http.CrossOriginProtection` lets a request through when `Sec-Fetch-Site` is `none` or `same-origin`, and extensions
with host access send one of those; CORS headers are irrelevant because the browser does not enforce CORS on them.
The 401 for a missing token still applies (`/v1/tasks` without a token: 401).

**Consequences.**

- **P14.2 is not needed as written** (extension origins bound to tokens, `If-Match`/`ETag` CORS). It becomes a
  documentation note; the issue is closed with a pointer here.
- The one origin gate that does exist is in the **native host**: it only answers a `chrome-extension://` caller whose
  id is in `server.allowed_origins` (in the E0.8 run without it, the host exited immediately: "Native host has
  exited"). Firefox is gated by `allowed_extensions` in the host manifest. **P14.3** (built-in ids) removes the need for
  anyone to type an id.
- Authentication is therefore the only gate for REST. That makes the scoped, revocable token (**P14.1**) and per-token
  rate limits (**P14.8**) more important, not less.
