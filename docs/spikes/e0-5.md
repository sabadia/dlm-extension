# E0.5: loopback fetch from the extension background

**Question.** Can the background of a Manifest V3 extension call the daemon on `127.0.0.1`, or does Chrome's Local
Network Access (Chrome 142 and later) or anything else get in the way?

**Result.** It works in both browsers. No prompt, no preflight, nothing to work around.

| Test (from the background, host access granted)                 | Chrome 156 headless | Chrome 156 headful | Firefox 159 |
| --------------------------------------------------------------- | ------------------- | ------------------ | ----------- |
| GET to the loopback collector                                   | 200                 | 200                | 200         |
| POST with `Content-Type: application/json` and `Authorization`  | 200                 | 200                | 200         |
| `fetch(..., { targetAddressSpace: 'loopback' })`                | 200                 | 200                | 200         |
| `fetch(..., { targetAddressSpace: 'local' })`                   | fails               | fails              | 200         |
| daemon `/v1/health`, `/v1/tasks` with token, `POST /v1/capture` | 200 / 200 / 201     | same               | same        |

- The collector saw **no `OPTIONS` request** from either browser: an extension with host access does not preflight.
- Chrome sent `Sec-Fetch-Site: none`, Firefox `same-origin`.
- `targetAddressSpace` is not needed. (`'local'` fails in Chrome because the target is loopback, not a private network.)

**Decision.** The extension calls the daemon directly with `fetch` from the background. The native host does **not**
need to proxy requests. The client keeps a small transport interface so that this could change, but no second
transport is planned.

**Not covered / to check by hand.** Branded Chrome refuses `--load-extension`, so these runs used Chrome for Testing.
It is the same engine and extension code; the manual checklist (E7.6) repeats the basic call in a normal Chrome.
Without host access (a user who removes it), requests fall back to ordinary CORS rules and would fail; the extension
must detect that and say so (see E0.9).
